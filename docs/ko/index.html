흐름

열 단계, 역할마다 다른 에이전트

역할은 서로의 작업 과정을 보지 않고 앞 단계가 남긴 파일만 받습니다. 쓴 팀은 자기 줄을 고르지 않고, CD는 어느 팀의 줄인지 모른 채 판정합니다. 런던 대행사 연구(Turnbull & Wheeler)가 기록한 24단계 가운데 아이디어를 내는 단계는 둘뿐이고 나머지는 과제 합의와 검증이었습니다. 이 스킬도 대부분의 단계를 거르고 고르는 데 씁니다.

  1. OT 01-client-brief.md

    받은 인자를 해석 없이 그대로 적습니다.

  2. 원자료 수집 02-raw.md

    제품 사실, 사람들이 실제로 쓴 말, 경쟁 문구를 원문 그대로 출처와 함께 모읍니다. 해석은 하지 않습니다.

  3. 플래너 03-creative-brief.md

    받은 과제를 "이 광고가 말할 것"으로 다시 정의합니다. 말할 상대 바꾸기, 문제 종류 바꾸기, 빈자리 찾기 가운데 하나를 쓰고, 근거가 된 한 장면을 원자료 번호로 가리킵니다.

  4. CD 크리에이티브 서저리 04-surgery.md

    브리프를 팀에 넘기기 전에 심사합니다. 돌려보내면 플래너가 한 번 고칩니다.

  5. 크리에이티브 팀 셋, 차례로 05-team-A/B/C.md

    팀마다 루트 3~5개, 33줄. 다음 팀은 앞 팀이 연 길을 "이미 나온 길"로 받고 다른 길을 찾습니다.

  6. CD 1차 리뷰 06-cd-review-1.md

    기준을 먼저 적고, 팀 이름을 가린 줄을 하나씩 살림과 죽임으로 판정합니다. 발전시킬 루트 3~5개에 피드백을 줍니다.

  7. 재작업과 변론 07-team-A/B/C.md

    팀은 살아남은 루트로 다시 쓰고, 죽은 줄 하나를 변론할 수 있습니다. 승인된 고객의 말이 있으면 원문 그대로 풀에 들어갑니다.

  8. CD 2차 리뷰 08-cd-review-2.md

    변론을 판정하고, 광고주에게 들고 갈 후보를 5줄 안팎으로 고릅니다.

  9. 광고주 09-client-review.md

    사실·규제 검수를 먼저 하고, 최종 한 줄과 대안 둘을 고릅니다. 확인이 필요한 사실에는 [의뢰인 확인 필요]를 붙입니다.

  10. 넘기기 10-final.md · 10-process-check.md

    최종 줄이 거쳐 온 길과, 각 단계가 업계 흐름대로 돌았는지 점검한 표를 냅니다.

또는 스킬 폴더에 복제

모든 프로젝트에서 쓰려면 사용자 스킬 폴더에, 한 프로젝트에서만 쓰려면 그 프로젝트의 .claude/skills/에 둡니다. 폴더 이름은 copy-masters로 합니다. 이때 스킬 이름은 /copy-masters, 업데이트는 git pull입니다.

모든 프로젝트 (macOS · Linux · Git Bash)

git clone https://github.com/5hyuns/ad-copy-agency-skill.git ~/.claude/skills/copy-masters

모든 프로젝트 (Windows PowerShell)

git clone https://github.com/5hyuns/ad-copy-agency-skill.git "$HOME\.claude\skills\copy-masters"

한 프로젝트에서만

git clone https://github.com/5hyuns/ad-copy-agency-skill.git .claude/skills/copy-masters

필요한 것은 Claude Code와 Python 3입니다(역할 사이에서 줄을 모으고 가리는 스크립트가 표준 라이브러리만 씁니다). 원자료 수집에 웹 검색 도구를 쓰고, 없으면 사용자 자료만으로 진행합니다. 새 세션을 열면 스킬 목록에 copy-masters가 보입니다.

시간과 비용

시연 기준으로 하위 에이전트 13개가 돌았고, 팀 셋을 차례로 돌려 20분 안팎(에이전트 실행 시간 합계 약 19분)이 걸렸습니다. 하위 에이전트가 쓴 토큰은 합쳐서 약 104만이었습니다. 한 줄 카피를 빨리 받고 싶을 때보다, 과정을 따라가 보고 싶거나 사실 검수가 중요한 광고에 맞습니다.

시연

가상 제품 고요베개로 한 번 돌린 기록

광고주 최종 “남편이 처음으로 제가 먼저 잠들었대요” 승인된 구매자 후기 원문. 대안은 변론으로 살아난 "각방 얘기는 30일 뒤에 해도 늦지 않아요."와 팀 B의 작동 장면 줄.

플래너는 말할 상대를 코 고는 사람에서 옆에서 깨어 있는 배우자로 바꿨습니다. CD는 첫 브리프를 한 번 돌려보냈습니다. 세 팀이 낸 루트 15개, 99줄의 판정과 이유를 모두 볼 수 있습니다.

시연 기록 보기
한계

단일 프롬프트보다 낫다는 근거는 없습니다

  • 같은 원자료를 받은 단일 프롬프트와 최종 줄을 비교한 시험에서, 이 스킬의 승률은 평균 0.37이었습니다. 결과는 단일 프롬프트보다 대체로 못하거나 비슷하다고 봅니다.
  • 쓸 이유는 과정에 있습니다. 업계 흐름을 단계별로 따라가 볼 수 있고, 브리프 대조와 광고주 검수가 단일 프롬프트에서 되풀이된 사실 오류(근거 없는 효능, 승인받은 고객 말의 임의 수정)를 막습니다.
  • CD와 광고주도 같은 모델입니다. 모델 판정은 독창성과 놀라움에서 사람과 잘 맞지 않는다는 연구가 있습니다. 같은 풀로 다시 돌려도 최종 줄이 크게 달라집니다.
  • 영어 카피는 미국 시장 가상 제품 하나로 한 번 시험했습니다. 실행은 끝까지 작동했지만 고른 3줄의 단일 프롬프트 상대 승률은 0.39였고, 가장 긴 최종 줄이 모든 쌍에서 졌습니다. 같은 후보로 광고주를 아홉 번 더 돌리니 매번 43자 대안 줄(단일 상대 0.67)을 골라, 0.39는 한 번의 선택에 크게 기댄 숫자입니다. 줄이 길어지는 곳은 CD 후보 단계가 아니라 팀 재작업입니다. 미국 규제표로 광고주가 고객 후기 한 줄을 FTC의 대표적 결과 규정(16 CFR 255.2)으로 뺐습니다.
  • 결과물은 헤드라인 줄입니다. 실무의 단위인 그림과 함께인 루트, 서브 카피, 본문은 이 스킬 밖에 있습니다.
  • 재료는 웹 원문과 사용자 자료뿐입니다. 시연, 포커스 그룹, 회의실의 한마디에서 나오는 재정의는 흉내 낼 수 없습니다.

copy-masters는 v1~v4에서 대가(Ogilvy, Bernbach, 다니야마, 정철)의 방식을 옮기던 때 붙은 이름입니다. v5는 그 구조를 내리고 대행사 작업 흐름을 따릅니다. 설계 근거는 잘 알려진 광고 25편의 제작 기록과 Turnbull & Wheeler의 대행사 연구에서 가져왔습니다. MIT 라이선스. GitHub 저장소
